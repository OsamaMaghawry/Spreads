# Reality check — 2026-W38 (14 Sep 2026)

Compares what the org's documents claim against what is actually true, right
now. Read-only — nothing here was fixed, only checked and, per the standing
rule, filed to `docs/ops/queue.md` as tickets. Ordered by consequence: money
and user-visible things first. Every finding says how it was verified.

**Headline: the network blocker from W36/W37 is still open (now two full
weeks), the exact "written and reviewed but never reaches a reader" failure
this job exists to catch has recurred on the blog's publish-to-production
step, and every single W37 weekly report — reality check, growth play,
branding audit, trading audit, board pack — is still sitting unmerged on an
orphan branch, exactly as W37's own reports were before someone manually
landed them.** None of that was landed for W37. The org is repeating the
failure the 7 Sep "Land the agent reports" commit was supposed to have fixed.

## 1. Blog: the exact outage this job exists to catch, recurring on a new step

**Claim (`content/PLAN.md`, `docs/context/org.md`):** the blog publishes one
new, fully-reviewed article every day, and content that reaches `main`
reaches the production blog.

**Reality, verified from the repo:**

- Today's daily pipeline **did** run (commit timestamps 11:12–11:24 UTC):
  `implied-volatility-options-explained` (foundations · 8) was drafted,
  fixed by desk-editor, adjusted by seo-editor, and marked "ship" by
  compliance-gate, all on the same claude/* branch, auto-merged to `staging`
  by `content-merge.yml` (commit `1fe3c4d`, confirmed an ancestor of
  `origin/staging`). This part of the pipeline is healthy.
- But **`docs/ops/queue.md` has carried an unresolved `needs owner` ticket
  since 2026-09-12**: `publish-blog.yml`'s `SUPABASE_SERVICE_ROLE_KEY`
  GitHub Actions secret is unset again (it was set once, 7 Sep, then is
  "not present now"). The workflow refuses to run rather than write with an
  empty key — which is correct behaviour — but the ticket's own text says
  plainly: **"no blog post merged to `main` reaches the production blog,
  including `option-delta-explained` in today's [12 Sep] release."**
- That ticket has not been touched since it was filed (`git log -p` on
  `docs/ops/queue.md` shows no edit to that entry after 2026-09-12; the most
  recent queue edit, `df5611c`, 09-14 09:24, touches a different entry
  entirely).
- Since then, `option-delta-explained` (12 Sep) and `theta-decay-explained`
  (13 Sep) have both been merged from `staging` into `main`
  (`git merge-base --is-ancestor <sha> origin/main` succeeds for both), which
  is exactly the push event `publish-blog.yml` listens for. **If the secret
  is still unset, both pushes failed at the credentials guard, and neither
  post reached the production `blog_posts` table** — meaning two more posts
  may currently be sitting in `main`'s `content/blog/` exactly the way the
  original two-week-empty-blog incident happened, and I cannot query
  `blog_posts` or fetch `deltamint.app/blog` to check either way (§0).
- **This is unverified but should be treated as true until someone checks
  the Actions run list or the live blog**, because the alternative — someone
  quietly re-added the secret and forgot to close the ticket — requires an
  action nobody logged anywhere I can find.

**Who fixes it:** the owner — add `SUPABASE_SERVICE_ROLE_KEY` back under
Settings → Secrets and variables → Actions on this repository, then
re-run the failed `publish-blog.yml` runs (or push a trivial `content/blog/`
change to re-trigger).

## 2. Every W37 weekly report is stranded on an orphan branch — again

**Claim (`docs/context/org.md` rhythm table):** reality check, vp-growth's
play, vp-product's backlog, head-of-branding's audit, head-of-trading's

**Reality:** all five non-daily W37 reports exist — the work was done — but

| Report | Commit | Branch |

| Reality check 2026-W37 | `f9c1b06` | `claude/lucid-mccarthy-qteu0h` |

Verified with `git merge-base --is-ancestor <sha> origin/main` and
`origin/staging` (both fail for all five) and `git branch -r --contains`
(each lives on exactly one orphan branch).

This is not a new failure mode — it is the **identical** failure the 7 Sep
commit `ad3eb33` ("Land the agent reports the digest was never able to
send") fixed for W36, by cherry-picking just the report files off eleven
stranded branches onto `main`. Nobody has done the equivalent for W37. The
W37 board pack (`3f91d5b`, read directly off its branch) already flagged
this exact problem — "the org now has 20 unmerged `claude/*` branches...
instead of last week's nine" — and it has gotten worse since, not better: as
of today there are 36 `claude/*` branches on the remote (`git branch -a`),
most containing exactly one week's stranded report and nothing else useful
to merge.

**Why it matters:** a cadence that writes a real, correct report nobody ever
reads is functionally identical to a cadence that ran and produced nothing —
the failure mode this reality-check job exists to catch — except it is
harder to notice, because the commit history *looks* healthy (36 branches,
lots of green runs) right up until someone checks whether any of it landed
anywhere a human or the next agent would look.

**Who fixes it:** owner or agent-manager — either repeat the `ad3eb33`
report-only cherry-pick for the five W37 branches above (and now W38's, once
this session pushes), or fix the underlying gap: nothing in this org merges
a report branch to `main`/`staging` automatically the way `content-merge.yml`
does for blog posts. That automation exists for content; it does not exist
for reports, and it is the same class of bug twice.

## 3. Pricing and feature docs describe a product that no longer exists

**Claim (`docs/product/pricing.md`, dated 2026-09-02):** a pricing page is
live at `/pricing` (old Pro $39/Desk $99 copy), to be replaced by a two-tier
Paper $0 / Live $29-$290 page "at the Stripe switch."

**Reality, verified from the code:**

- **There is no `/pricing` page at all**, and has not been since 12 Sep.
  `landing/public/` (the static asset directory actually deployed) has no
  `pricing/` folder — only `terms/`, `privacy/`, `assets/`. The only copy of
  the old pricing page left in the repo is `landing/drafts/pricing/index.html`,
  explicitly moved out of the served directory. `landing/src/index.js`'s
  sitemap function and its own comment say so directly: *"No /pricing. The
  page is unlinked... `/pricing` now returns the 404 page, the nav and
  footer links are gone from every page, and the path is out of the
  sitemap."* (commit `95b03b7`, 12 Sep, quoting the owner: *"hide the pricing
  page... the product increased, so we may revise the pricing again."*)
- **The whole product is in Demo Mode**, seeded on by default
  (`supabase/migrations/0035_demo_mode.sql`, 12 Sep): live accounts cannot
  open new orders at all ("watch-only"). A second migration the same day
  (`0040_paper_only.sql`) goes further — a live account is excluded from
  every scheduled read too (`syncTrades`, `equityHistory`, `positionWatch`,
  `weeklyDigest`), also seeded on by default. Both migrations are ancestors
  of `origin/main`, so the code implementing this has shipped; whether the
  row itself has been applied on the production database I cannot check
  (§7), but the code's own default (missing row ⇒ demo mode true) makes that
  close to irrelevant.
- **Neither `pricing.md` nor `features.md` mentions any of this.** Both are
  still dated 2026-09-02 and describe a product where live accounts trade
  normally and are the thing being sold ("PAID on live" tags on ~20 rows of
  `features.md`). Right now, the thing `features.md` says is the entire paid
  tier — live trading — is switched off product-wide, by the owner's own
  instruction, for reasons ("I need to share and I need feedback") that have
  nothing to do with the pricing numbers either document argues about.

**So the task of "confirm the pricing page matches two tiers, Paper free /
Live $29-$290" cannot be answered as asked: there is currently no pricing
page to compare, live or otherwise, and the document that claims one exists
is stale about that fact, not just about the numbers.** This is drift in the
document, not a defect in the product — hiding pricing during a demo/feedback
phase reads as a deliberate, reasonable owner call. The gap is that nobody
updated `pricing.md` or `features.md` to say so.

**Who fixes it:** vp-product — a two-line update to both docs noting Demo
Mode supersedes the pricing/feature-gating sections until the owner turns
it off, so the next reader (agent or person) doesn't plan against a page
that was taken down two days after the doc's own "current state" was written.
