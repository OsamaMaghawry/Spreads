# Branding consistency audit — 2026-W39

Cadence: biweekly, odd ISO week → full sweep across every surface. This is
the second cycle; the first baseline is `docs/branding/2026-W36.md`. Where a
W36 finding recurs, this run cites the current file:line (several moved) and
says explicitly whether it is fixed, open, or partially fixed, rather than
re-describing it as new.

Scope walked: the app (`src/`), the landing site (`landing/`), the blog
(`content/blog/`), auth + alert/digest emails (`supabase/auth/`,
`supabase/functions/`), the exported PDF
(`src/components/analysis/ExportPdfButton.jsx`). Live-site check
(`deltamint.app`, `dashboard.deltamint.app`) via WebFetch returned
`EGRESS_BLOCKED` again this cycle — unchanged from W36 and consistent with
`docs/context/reachable.md`'s 2026-09-04 row (403 at CONNECT, a proxy policy
block, not a site-side issue). Not verified against the deployed site this
cycle either; source only.

Truth of claims is desk-editor's question; disclosure sufficiency is
compliance-gate's. Neither is judged here — flagged and handed off where it
came up.

## Verdict on the W36 top five

   `dm-*` token usage did spread since W36 (now referenced in ~24 files,
   including `Dashboard.jsx`, `AccountDetail.jsx`, `AccountHistory.jsx`,
   `Accounts.jsx`, `Billing.jsx`, `OptionChain.jsx`, `Layout.jsx` nav — real
   progress in the reading chrome). But the primary-action buttons on the
   login → scan → trade path are the same three colors as W36, same call

   the renamed `Screener.jsx`), emerald on "Connect Alpaca" submit

   still defaults `tone="emerald"`, and Login/Register still ride shadcn's
   default near-black `--primary: 0 0% 9%` (`src/index.css:15`) via the
   generic `<Button>` (`src/pages/Login.jsx:95`).

2. **Positions Monitor naming split — PARTIALLY FIXED, reshaped by an
   intervening rename.** The nav/H1 half is genuinely fixed: `Layout.jsx:66`
   and `Dashboard.jsx:58` both now read `"Dashboard"` (`e9330ff`). But the
   canonical name itself changed under this — the owner renamed "Positions
   Monitor" → "Dashboard" on 12 Sep, and brand.md's feature table now lists
   **"Positions Monitor" as the forbidden synonym**, inverted from W36. The

   `./public`). That draft still says **"Positions Monitor"** twice
   (`landing/drafts/pricing/index.html:156,196`) — now the forbidden name —
   and reintroduces the split the moment it publishes unedited. Zero exposure
   today; a landmine, not a live defect (item 7 below).

5. **Green used decoratively as well as semantically — STILL OPEN, same

## New findings since W36

**A. Every foundations blog post published since brand.md wrote the
900–1,300-word rule blows through it — several worse than the post the rule
was written to prevent.** brand.md (lines 111–113) is explicit and calls
`credit-spread-max-loss` (2,143 words) "what this rule exists to prevent."
Body word counts, frontmatter stripped, of foundations posts published after
the rule existed and after passing desk-editor/seo-editor review:
`option-assignment-what-happens.md` — 2,385 words (2026-09-21),
`gamma-options-meaning.md` — 2,122 words (2026-09-20),
`implied-volatility-options-explained.md` — 1,926 words (2026-09-14),
`early-exercise-options.md` — 1,891 words (2026-09-22),
`what-is-an-options-contract.md` — 1,764 words (2026-09-07),
`what-happens-options-expiration.md` — 1,761 words (2026-09-23, today).
Five of six exceed the original violator. Diagrams checked separately and
are fine (e.g. `gamma-across-moneyness.svg` carries 10 words, under the
15-word cap) — this is a length failure, not a diagram failure. Length isn't
an explicit checkpoint anywhere in the daily pipeline
(content-engine → seo-editor → desk-editor → compliance-gate), which is why
truth and SEO reviews pass it through unchanged.

**B. The wordmark's own "mint" renders in two different greens, app vs.
landing — the logo itself, not a secondary surface.** brand.md fixes "mint in
the green (`#3FA672`)." App: `Wordmark.jsx:96` sets `text-dm-mint` =
`#3FA672`. Landing: `.brandmark .m { color: var(--mint); }`
(`landing/public/assets/site.css:170`) resolves to `--mint: #2E8B5F` in light
mode and `#5FC48D` in dark mode (`site.css:19,32`) — neither matches. This
sits directly beneath the recent lockup-geometry rework (`386841d`, `9b67a8e`,
`507dc15`, `2858a90`), which did land correctly: the ink-centering math
(`MARK_RATIO`, `GAP_RATIO`, `WORD_INK_CENTRE`, `MARK_DROP`) is now
byte-identical between `src/components/brand/Wordmark.jsx:20,26,50-72` and
`landing/public/assets/site.css:133-164` — the geometry drift brand.md
documents (24/22/28/20px, 1.54× mark) is genuinely fixed, one formula driving
every instance. The color of half the word is the one seam left in an
otherwise-unified lockup.

**C. `docs/context/brand.md` itself is stale on the geometry it documents —
the book vs. the code, not a cross-surface bug.** brand.md lines 39–63
describe a formula keyed on `EM_PER_PX` (`1.0804`) "in
`src/components/brand/DeltaMintMark.jsx`." That constant no longer exists
anywhere in the repo (confirmed by reading the file in full and grepping) —
the current implementation (`Wordmark.jsx`) uses a different, ink-centering
formula and gives a smaller tight-crop mark than the book's worked example
implies. `landing/public/assets/site.css:130`'s comment carries the same
stale cross-reference. Recorded as a brand.md-accuracy defect, proposed to
vp-product below rather than edited directly.

## This cycle's asks (top five, ranked by exposure)

**1. Two parallel design systems — three different "primary action" colors
on the login → scan → trade path.**
Surfaces: the whole app, every trader, every session (W36 item 1, unchanged).
Emerald (`Scanner.jsx:223`, `AccountForm.jsx:120`, `ExportPdfButton.jsx:286`,
`ConfirmSubmit.jsx:16` default) vs. shadcn near-black (`src/index.css:15`,
`Login.jsx:95`) vs. `dm-accent` purple (nav, Admin).
**Fix:** repoint the app's primary-button/focus-ring styling at `dm-accent`;
retire the ad hoc emerald and shadcn-default buttons. Style-only, no copy or
feature change.

**2. Foundations blog posts blow the brand book's own hard 1,300-word
ceiling — worse than the case the rule was written to prevent.**
Surfaces: `content/blog/` — organic acquisition, top of funnel.
`option-assignment-what-happens.md` (2,385 words), `gamma-options-meaning.md`
(2,122), `implied-volatility-options-explained.md` (1,926),
`early-exercise-options.md` (1,891), `what-happens-options-expiration.md`
(1,761), `what-is-an-options-contract.md` (1,764) — all against brand.md's
1,300-word ceiling and its own precedent, the 2,143-word
`credit-spread-max-loss`.
**Fix:** split each over-cap post into two, or cut to the ceiling, worst
offenders first (`option-assignment-what-happens.md`,
`gamma-options-meaning.md`); add an explicit word-count pass/fail gate to the
daily content pipeline so this stops reaching publish.

**3. Red (loss/risk) now renders as six colors instead of five, and the
newest one arrived after brand.md fixed the rule.**
Surfaces: app-wide P/L, landing, exported PDF (W36 item 4, now worse).
`dm-negative` used once (`OAuthCallback.jsx:109`); ~55 files still on
`rose-6xx/7xx`; landing's own `--rose` (`site.css:20,42`); shadcn
`--destructive` (`index.css:23`); PDF paper banner hardcoded
`rgb(180,72,92)` (`ExportPdfButton.jsx:130`); **new** PDF "unattributed" text
hardcoded `rgb(160,60,60)` (`ExportPdfButton.jsx:139,160`) — a sixth red
matching none of the other five.
**Fix:** collapse to `dm-negative`/`dm-warning` everywhere, PDF included —
this answers brand.md's own "(proposed)" question, it is not a new ask.

**4. The wordmark's own "mint" is two different greens depending on
domain — the logo itself, one click apart, on the site's highest-traffic
surface.**
Surfaces: every page of `deltamint.app` (nav + footer,
`landing/public/assets/site.css:170,19,32` → `#2E8B5F`/`#5FC48D`) vs. every
page of the app (`src/components/brand/Wordmark.jsx:96` → `#3FA672` via
`dm-mint`).
**Fix:** set `--mint` in `site.css` to `#3FA672` (light) and define
`dm-mint`'s dark-mode equivalent, so the logotype is one color everywhere,
independent of the rest of item 11/the landing-palette question below.

**5. The Analysis feature still carries three names inside one user
action, including on the one document that leaves the product.**
Surfaces: `AccountAnalysis.jsx`, its exported PDF (W36 item 3, unchanged).
On-screen H1 "Analysis" (`AccountAnalysis.jsx:508`) vs. PDF `title` prop
"Performance Analysis" (`AccountAnalysis.jsx:536`) vs. footer "economic
performance report" both on-screen (`AccountAnalysis.jsx:715`) and in the PDF
(`ExportPdfButton.jsx:185`).
**Fix:** `AccountAnalysis.jsx:536` title prop → `` `${name} — Analysis` ``;
both footer strings → "Analysis."
**Hand-off, unchanged from W36:** whether "economic performance report" is a
deliberate disclosure choice, rather than an accident, is desk-editor's/
compliance-gate's call before the wording is simply replaced.

## Proposed rules for `brand.md` (vp-product to accept)

- *"Blog word-count and structure (the Investopedia shape) is checked as an
  explicit pass/fail gate before a post is marked ready to publish, not only
  folded into desk-editor/seo-editor review."* (closes finding A — truth and
  search review already run on every over-cap post and none of them catch
  length)
- *"Any hardcoded RGB triple introduced for PDF or email text must be one of
  the `dm` hexes, named as such in a comment — no new ad hoc color may be
  added to `ExportPdfButton.jsx` without a corresponding `dm` token."*
  (closes the sixth-red regression in ask 3, which happened specifically
  because no such rule existed)
- Replace brand.md's geometry table (lines 39–63) with the current
  `Wordmark.jsx` constants and drop the stale `EM_PER_PX` cross-reference
  (also stale in `site.css:130`'s comment) — text proposed above in finding
  C, vp-product to accept the actual rewrite.
- Reaffirms the W36-proposed rule, still open: red/green are semantic, never
  decorative; the app's Tailwind emerald/rose/amber/sky/violet usage does
  **not** get sanctioned as-is — it collapses into the `dm` scale (asks 3/4,
  item 6); lifecycle-status chips (item 10) get a single neutral treatment
  instead of a rainbow of hues.
