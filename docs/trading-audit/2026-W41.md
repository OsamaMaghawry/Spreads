## Findings

### 1. Pairing of untraceable shorts is still order-dependent (carried from W36 #1) — EXECUTED

`spreadPairing.ts` `pairSide`. Same four live put legs (short 100, short 98,
long 97, long 90), only the input order differs:

```
[100s, 98s, 97L, 90L] → 100/97 (3-wide) + 98/90 (8-wide)
[98s, 100s, 97L, 90L] → 98/97 (1-wide)  + 100/90 (10-wide)
```

Max risk on the 100-strike short swings from a 3-wide to a 10-wide spread
(≈ +$700 per contract of displayed risk, 3.3×) with no trade in between. Broker
position order is not a documented contract. Reach: legs with no filled
multi-leg order to prove the pairing (legged-in, partial closes, remainders).
Fix shape: sort shorts by a stable key (strike, proximity to the nearest long)
and pair globally-nearest first. No ticket existed for this; one is filed now.

### 2. An adjusted spread's max risk still enters the account total (carried from W36 #2) — EXECUTED + READ

`totalRisk([{type:"put_spread", adjusted:true, maxRisk:183}])` →
`{risk:183, complete:true}`. `syncAccounts` (now `accountSync.ts`) computes
`maxRisk` for every flat spread before attaching `adjusted`, and `totalRisk`
only withholds on a null `maxRisk`. The row withholds on screen; the account
total and `riskComplete` do not. House rule: the figure must be null on an
adjusted row so `riskComplete` goes false. No ticket existed.

### 3. A long-call-covered short is called "covered call" with a −$1.00 break-even — EXECUTED

Fixtures (no order history, so the legs fall to the loose path):

```
long 50C @3 + short 55C @1  → covered_call(short): risk 0, breakEven -1.00 ; long_option: risk 300
long 55C Dec @3 + short 55C Nov @1 → covered_call(short): risk 0, breakEven -1.00 ; long_option: risk 300
```

`breakEvenOfKind(COVERED_CALL)` is `shareBasis − credit` and `shareBasis` is
unset when the cover is a long call, so `0 − 1 = −1`. A negative stock price
reaches the card (`PositionCard.jsx:17`, `SpreadTable.jsx:240` render
`fmtMoney(s.breakEven)`). The label is also wrong for the first shape (a call
debit vertical, not a covered call) and the two rows' risks sum to $300 where
the pair's bound is the $200 debit — conservative, but a seam. Withhold
break-even (null) when `coverLongs` is the only cover and name the structure
"call spread / diagonal (unproven)" or leave the label generic.

### 4. Short stock is shown as a long share lot with a bounded max risk — EXECUTED

Input: stock position qty −100 @ $48, short 55C. Output: the call is correctly
`naked_call` (risk null), but the share row is `shares`, **qty 100**, maxRisk
**$4,800**, break-even $48 — sign dropped by an `abs()` in the lot, risk
computed as a long's cost. A short stock position's loss is unbounded to the
upside; the row presents a $4,800 ceiling. Margin accounts can hold short
stock (a called-away or manually shorted position). Withhold risk and label the
lot "short shares" (or carry the sign) rather than mirror it as a long.

### 5. Implied-vol fallback of 0.25 fabricates deltas — EXECUTED (low)

`optionScan.ts` `impliedVol` returns 0.25 whenever the bisection cannot bracket
(price below intrinsic, crossed or stale mid). `optionDelta(9, 100, 110, 30d,
put)` → **−0.894** from the invented vol, and `nearestDelta` / the setup's
displayed delta use it. Impact is small for the 12–22 delta band (a garbage mid
rarely lands there), but it is a default where "no delta" belongs: return null
and have `scanChain` drop the strike.

### Observations (read-derived, not filed as defects)

- `classifyLeg` calls every lone short put `cash_secured_put` without checking
  cash (documented as deliberate: Alpaca levels 1–3 cannot hold an uncovered
  put). The label is a broker-entitlement claim, not a measurement; a margin
  account short a put with thin cash still reads "cash-secured". Acceptable
  while Alpaca is the only broker — **revisit before the Tradier/SnapTrade
  accounts see this path** (`broker/snaptrade-tradier` branch).
- `nakedShortCalls`: any long call on the name expiring on/after the short
  covers it regardless of strike distance (short 100C / long 200C reads as
  covered, bounded risk $10,000/contract). Correct as "defined risk"; the watch
  gives it no signal. Informational.
- Short stock correctly does not cover calls in `sharesByTicker` (executed:
  short 100 sh + short 55C → naked critical). Good.
- Executed OK: CSP risk `(strike − credit) × 100` = $4,850 on a $50/1.50 put;
  covered call 1-of-150 shares + 2 short calls splits 1 covered / 1 naked
  (risk null); wheel prefix with adjusted basis $47 → CC break-even $46, shares
  $4,600, CSP break-even $44; a missing `current_price` leaves the CSP row's
  risk unchanged (no price dependency) — no default seen.
- `price_untrusted` (read: `positionWatch/index.ts:55–68, 129`) still withholds:
  no spot or untrusted spot records the ticker as unjudged and raises an `info`
  note instead of through/near-strike. `naked_short_call` fires at any price.
  `cover_unjudged` replaces the false critical on adjusted contracts.
- Staging refactor: `accountSync.ts`, `entryScan.ts`, `chainRead.ts` diffed
  against `main`'s function bodies — import paths and the request wrapper only;
  logic is unchanged. Per AGENTS.md, every function importing a changed
  `_shared/` file must be redeployed; the three now-thin functions plus `mcp`
  are the importers.
- Connector read path (`connectorTools.ts`, read): money figures pass through
  `r2` (null stays null); `total_max_loss` is null when `riskComplete === false`
  (inherits finding 2 until fixed); `return_on_risk_pct` guards `maxRisk > 0`.
  No write path: no broker POST, no insert/update/upsert/delete in the tool file.
  The invariants (max-loss check, `refuseMassDelete`, snapshot-before-write) sit
  on order/sync write paths the connector does not call — confirmed by absence,
  not by running it.
