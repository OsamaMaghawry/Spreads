## Findings

### 1. Cover allocation hands a long to the wrong short → false NAKED call — EXECUTED (new)
`callCover.allocateCallCover` (`callCover.ts`, longPool loop) gives each short, shortest-dated
first, the *first eligible long in input order*, not the long that expires
soonest. A late-dated long can be burned on an early short, leaving a later
short with no eligible long.

Case (XYZ calls, same strike): shorts A exp 2026-10-16, B exp 2026-11-20;
longs L1 exp 2026-12-18, L2 exp 2026-10-30.
```
input [A,B,L1,L2] → A uncovered 0, B uncovered 1   (B shown NAKED)
input [A,B,L2,L1] → A uncovered 0, B uncovered 0   (all covered)
```
Same four contracts, order is the broker's list order. Valid allocation
(A→L2, B→L1) exists. Consequence: the dashboard prints "Naked call · Unlimited"
and `positionWatch` raises a **critical** on a fully defined-risk calendar/diagonal book;
the same allocator feeds `freeCallCover`, so the Scanner/ticket also mis-state
which long is free. It is the false-critical shape the 8 Sep TSLA incident was
about. Fix: sort `longPool` by expiry ascending (earliest sufficient first) before
allocating. Owner: duty-engineer (plain bug, no meaning change).

### 2. `pairSide` is still order-dependent (W36 #1) — EXECUTED, re-confirmed
Queue ticket 2026-09-09 already open. Via `pairSpreads`, puts 100s/98s/97L/90L:
```
[100s,98s,97L,90L] → 100/97 (w3) | 98/90 (w8)
[98s,100s,97L,90L] → 98/97 (w1)  | 100/90 (w10)
```
Same account, no trade between: the 100 short's width swings 3→10, max risk by
≈$700/contract (less credit). Position order from Alpaca is not a stable
contract. `tradeReconstruction.nearestLong` same shape, read-derived.

### 3. Adjusted spread's max risk still enters the account total as complete (W36 #2) — EXECUTED (reducer), read-derived (syncAccounts)
`totalRisk([{type:"put_spread",adjusted:true,maxRisk:183}])` →
`{risk:183, complete:true, undefinedRisk:[]}`. `positionKinds.totalRisk` has no
knowledge of `adjusted`; `syncAccounts` (line 561) feeds it unfiltered. Per-row
figures are withheld; the account total is not. Fix: treat `adjusted` as null risk in the reducer.

### 4. Short stock is shown as a long share row with bounded risk — EXECUTED (new)
`pairSpreads([stock qty -100 @100])` → `{type:"shares", qty:100, maxRisk:10000,
breakEven:100, collateral:10000}`. The sign is lost: a short position, whose loss
is unbounded, renders as 100 long shares with a $10,000 max risk. (It does not
wrongly cover a short call — that fixture returned `naked_call` — so cover
arithmetic is unaffected.) Withhold rather than default: a short share row must
be risk-null / "Unlimited", not abs-qty long. Escalate-class (changes what a
number means) — owner decision on presentation.
